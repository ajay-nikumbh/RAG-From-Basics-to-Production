# 06. Similarity Measures

In this note:

- How we measure "closeness" between two vectors
- Dot product, cosine similarity and Euclidean distance, with formulas
- A full worked example by hand
- Which measure to use and why normalised vectors make them agree

## The problem

After embedding, every chunk and every question is a vector. Retrieval needs one number that says **how similar** a chunk vector is to the question vector. Three measures are common.

Notation used below. Two vectors with $n$ numbers each:

$$\mathbf{a} = (a_1, a_2, \dots, a_n), \qquad \mathbf{b} = (b_1, b_2, \dots, b_n)$$

## 1. Dot product (inner product)

$$\mathbf{a} \cdot \mathbf{b} = \sum_{i=1}^{n} a_i \, b_i = a_1 b_1 + a_2 b_2 + \dots + a_n b_n$$

In words: multiply the numbers in the same position, then add all the results.

- Bigger value = more similar.
- Depends on both the **direction** and the **length** of the vectors.
- This is the score used by DPR in the original RAG paper: $d(z)^\top q(x)$ is the dot product of a document vector and a question vector. Finding the top results by dot product is called **Maximum Inner Product Search (MIPS)**.

## 2. Cosine similarity

$$\cos(\theta) = \frac{\mathbf{a} \cdot \mathbf{b}}{\lVert \mathbf{a} \rVert \, \lVert \mathbf{b} \rVert}$$

where the **length** (also called norm or magnitude) of a vector is:

$$\lVert \mathbf{a} \rVert = \sqrt{a_1^2 + a_2^2 + \dots + a_n^2}$$

In words: the dot product divided by the two lengths. This keeps only the **angle** between the vectors and ignores their length.

Cosine similarity is the most common measure for text embeddings.

## 3. Euclidean distance (L2 distance)

$$d(\mathbf{a}, \mathbf{b}) = \sqrt{\sum_{i=1}^{n} (a_i - b_i)^2}$$

In words: the straight-line distance between the two points.

- **Smaller value = more similar** (it is a distance, not a similarity).
- 0 means identical vectors.

**Dot products**

- q . c1 = 0.9 x 0.8 + 0.1 x 0.2 + 0.2 x 0.1 = 0.72 + 0.02 + 0.02 = **0.76**
- q . c2 = 0.9 x 0.1 + 0.1 x 0.9 + 0.2 x 0.3 = 0.09 + 0.09 + 0.06 = **0.24**

**Lengths**

- |q| = sqrt(0.81 + 0.01 + 0.04) = sqrt(0.86) = 0.927
- |c1| = sqrt(0.64 + 0.04 + 0.01) = sqrt(0.69) = 0.831
- |c2| = sqrt(0.01 + 0.81 + 0.09) = sqrt(0.91) = 0.954

**Cosine similarity**

- cos(q, c1) = 0.76 / (0.927 x 0.831) = 0.76 / 0.770 = **0.987**
- cos(q, c2) = 0.24 / (0.927 x 0.954) = 0.24 / 0.884 = **0.271**

**Euclidean distance**

- d(q, c1) = sqrt((0.1)^2 + (-0.1)^2 + (0.1)^2) = sqrt(0.03) = **0.173**
- d(q, c2) = sqrt((0.8)^2 + (-0.8)^2 + (-0.1)^2) = sqrt(1.29) = **1.136**

## Why normalised vectors make all three agree

If every vector is **normalised** to length 1 (most embedding models do this, or you can do it yourself):

- Cosine similarity = dot product, because the lengths in the denominator are 1.
- Euclidean distance becomes a simple function of cosine:

$$\lVert \mathbf{a} - \mathbf{b} \rVert^2 = 2 - 2\cos(\theta) \quad \text{when } \lVert \mathbf{a} \rVert = \lVert \mathbf{b} \rVert = 1$$

So ranking by any of the three gives **the same order**. In practice: normalise vectors, then use dot product, because it is the cheapest to compute.

## Top-k

**Top-k** means: score the question against chunks and keep the **k** highest-scoring ones (for example k = 4). Note 08 covers how to choose k. Note 07 covers how to find the top-k fast without scoring every chunk.

## Key points

- Dot product: multiply and add. Cosine: dot product divided by lengths, keeps only the angle. Euclidean: straight-line distance.
- Higher is better for dot and cosine, lower is better for Euclidean.
- On normalised vectors all three give the same ranking.
- The RAG paper uses dot product (Maximum Inner Product Search).
